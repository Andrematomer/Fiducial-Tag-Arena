How it works

  • One detection per frame, not a live loop. Each tag is run one at a time, in a rotating order, so no two detectors compete for the CPU while being timed.
  • Timing covers only the detector call (performance.now() before and after). Frame synthesis, grayscale conversion for AprilTag, and drawing are excluded. ArUco’s library converts RGBA to gray internally, so that step is included for ArUco. Browser timers are coarse (around 0.1 ms), so very fast detections are rounded.
  • Success means the detector returned the correct ID with its centre within 25% of the tag side from the true centre. Anything else (missed, wrong ID, wrong place) is a failure.
  • Fairness. The black outer square of every tag is drawn at the same pixel size and pose. Shape positions, noise and all random parameters come from the same seeded streams for every tag in a tick.
  • Not apples-to-apples by design. Tags differ in ID capacity, pose output and intended use. This page measures only how reliably each one is found under bad conditions.
  • Results depend on the JavaScript/WASM implementations used here, not necessarily on the original papers’ detectors.

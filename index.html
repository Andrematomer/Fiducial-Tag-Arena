Fiducial Tag Arena

Stress-test fiducial marker detectors in your browser. Every frame is generated at runtime and every tag gets the exact same degraded conditions. Tick a tag to enable it (its detector downloads only then), then press Run once.

How it works

  • One detection per tick, not a live loop. Each enabled tag is run one at a time (the highlighted window), starting from a different tag every tick, so no two detectors compete for the CPU while being timed.
  • Run once = one tick. Every tick draws a new seed, so random IDs, occluder placement, noise and (in Random mode) all parameters change, but identically for every tag.
  • Timing covers only the detector call. Rendering the frame is never included. It is not perfectly even: ArUco’s call also includes its own RGBA→gray conversion, and AprilTag’s includes copying the image into WASM memory and parsing its JSON result. Browser timers are coarse (about 0.1 ms).
  • Success means the detector returned the correct ID with its centre within 25% of the tag side from the true centre. A miss, a wrong ID or a wrong place all count as failure. The strip under each tag shows the last 128 ticks; the percentage covers all ticks.
  • Camera model. Tag size is the zoom; the lens-shift sliders work like Blender’s camera shift: the tag stays in the middle of the frame while being viewed off-axis, which adds perspective and lens distortion as if it were near the frame edge. If a rotated plane would pass through the camera it is pushed back automatically.
  • Preview. The top-right window shows a blank plane with exactly the slider values (the maximum in Random mode). Use the three round buttons on it: drag to rotate, zoom, or shift.
  • Not apples-to-apples by design. Tags differ in ID capacity, pose output and intended use. This page measures only how reliably each one is found under bad conditions. Results reflect the JavaScript/WASM implementations used here, not necessarily the original papers’ detectors.
